# Landing page

The Home screen is a product introduction and an entry into the existing designer. It uses the Open Reports blue with an ink and off-white palette, document illustrations, and previews generated by the reporting engine.

## Page structure

1. **Hero** (always dark). Headline, one primary action (**Try the designer** opens the complete invoice with the first-edit guidance), **Watch it work**, and the hero scene: an `invoice.json` card whose fields stream into a sheet of paper that assembles itself (customer name, rows, counted total, PAID stamp) and then leaves as PDF/DOCX/XLSX/ZPL. Visitors can type a customer name; the loop then holds the finished page so their value is the only change. The values are fictional and the scene is illustrative, not a render.
2. **Format marquee**: output formats and document types.
3. **Why switch** (`#why`): a before/after slider comparing the same heading and total as JRXML and as Open Reports JSON (line counts are computed from the snippets), then a category comparison with classic report servers, commercial JS SDKs and document-template APIs. Facts are kept at category level and footnoted with their date; revisit the prices when they change. Below 800 px the two panes stack.
4. **Features** (`#features`): six capability tiles with small looping illustrations.
5. **Workspace** (`#workflow`): the designer screenshot tilts flat as it scrolls into view, followed by three steps.
6. **Real output**: the report showcase with engine-generated previews.
7. **Templates** (`#templates`), **Developers** (`#developers`), **Create** (`#create`): unchanged workflows, including the replacement confirmation for starters.
8. **Closing band** with the primary action and a GitHub star request.

The GitHub star button reads the public repository count once per session and shows it only from 50 stars; offline or rate-limited requests leave the button without a count. Star requests appear only after the product has been shown (developer band, closing band) plus the header button.

## Colour and motion

The landing tokens in `landing.css` share one cool ink family with the hero (`--hero-*` in `landing-motion.css`), in light and dark interface themes. Every text node was checked against its effective background at WCAG AA (4.5:1, or 3:1 for large text) in both themes; recheck after changing a token.

Motion uses transforms and opacity only. Scroll reveals hide content only after `useLandingMotion` adds `.motion-ready`, so content stays visible without JavaScript. With `prefers-reduced-motion`, all animation stops, the hero scene shows its finished state and the marquee becomes a static list.

## Assets

`apps/designer/public/landing/reports/*.webp` are first-page PDF previews generated from the committed sample report definitions at `effa0e7` through `POST /api/v1/render`. All data and branding are fictional. The twelve previews cover documents, retail, healthcare, printing, education, logistics, manufacturing, and summaries. Templates without a rendered preview use a decorative document graphic, which is not presented as a PDF screenshot.

`apps/designer/public/landing/designer.webp` is a capture of the actual light-theme designer with the invoice example. Refresh these assets when the corresponding example or designer appearance changes. Generate the sample PDF, rasterize its first page with Poppler at up to 960 pixels, then encode WebP. Keep the designer screenshot at 1600 × 880 pixels. The complete asset set is approximately 408 KB; gallery and designer images load lazily.

## Interaction and accessibility

The layout adapts down to 320 pixels. The mobile navigation closes on Escape, an outside click, or a destination choice. Buttons retain visible keyboard focus, preview/category selectors expose their pressed state, the gallery announces its result count, and decorative art is hidden from assistive technology. Motion respects `prefers-reduced-motion`. Light, dark, and system appearance continue to use the saved interface preference.

## Learning and capability dialogs

The Learning Studio uses compact poster rows, topic filtering, search, and a video player with English captions. Previous/next controls remain visible on desktop, and the example action follows the lesson: document imports open their import flow, developer lessons open API settings, and report examples use the existing replacement guard. The player shows a retry action when a video cannot load.

On phones, Browse lessons scrolls to the library; choosing a lesson returns to the player and focuses it. The capability explorer groups its seven starting workflows into Create & improve and Deliver & share. Both dialogs use the existing modal focus trap, Escape and outside-click dismissal, and the interface appearance preference.
